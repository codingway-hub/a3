## 2. 统一事件 Schema（pkg/schema）

全系统最核心规范。终端产出、服务端消费的唯一结构。

```go
package schema

type Severity string // "low" | "medium" | "high"
type RiskAction string // "alert" | "block"

type RiskTag struct {
    Code        string     // 如 dlp.aws_access_key、cmd.git_force_push、file.sensitive_read
    Name        string     // 中文名称（告警展示用）
    Severity    Severity
    Action      RiskAction
    MatchedRule string     // 规则 ID
    Snippet     string     // 命中内容片段（已脱敏）
}

type ToolOutput struct {
    IsError bool   `json:"is_error"`
    Summary string `json:"summary"` // 截断后的结果摘要（上限 4KB）
}

type Event struct {
    EventID      string            `json:"event_id"`      // 幂等键 = ClaudeCode 日志行原生 uuid
    EventType    string            `json:"event_type"`    // session_start|conversation|tool_call|tool_result|session_end
    AgentType    string            `json:"agent_type"`    // "claude-code"
    SessionID    string            `json:"session_id"`
    DeviceID     string            `json:"device_id"`
    OccurredAt   time.Time         `json:"occurred_at"`   // 日志行 timestamp 字段
    Role         string            `json:"role,omitempty"`          // conversation: user|assistant
    Content      string            `json:"content,omitempty"`       // Prompt 或回复文本
    ToolName     string            `json:"tool_name,omitempty"`
    ToolCallID   string            `json:"tool_call_id,omitempty"`  // 关联 call↔result
    ToolInput    json.RawMessage   `json:"tool_input,omitempty"`
    ToolOutput   *ToolOutput       `json:"tool_output,omitempty"`
    SourceMethod string            `json:"source_method"` // file_log|hook
    RiskTags     []RiskTag         `json:"risk_tags,omitempty"`
}
```

约束：
- `EventID` 全局唯一，服务端以主键 `ON CONFLICT DO NOTHING` 实现去重幂等，重试安全。
- `Content`/`ToolInput` 在终端出站前经过通用脱敏管道（可配置开关）。
- Schema 变更只允许追加可选字段，长期兼容不破坏（架构约束 §6）。

上报信封：

```
POST /api/v1/events/batch
Authorization: Bearer <device_token>
{
  "events": [Event...],          // ≤500 条/批
  "device": {"device_id":"", "hostname":"", "os":"", "arch":"", "agent_version":"", "plugins":["claude@v1.0.0"]}
}
→ 200 {"accepted":n,"duplicates":m}
```

## 3. 终端 Core 与插件接口

### 3.1 Plugin 接口（internal/agent/core/plugin.go）

```go
type Plugin interface {
    Name() string
    Version() string
    LogWatchSpecs() []core.LogWatchSpec          // 监听路径 glob + 解析器绑定
    ParseLine(path string, line []byte, offset int64) ([]schema.Event, error)
    InterceptHandlers() []core.InterceptHandler  // 如 preToolUse hook 处理器
    BuiltinRules() []rules.Rule                  // 预置风控规则（终端本地判定用）
    Setup() error                                // 安装动作（如写 hook 配置）
}
```

- 新增 Agent = 新建插件包 + `registry.Register(...)` 一行，Core 零改动。
- 一期通过构建期注册；接口即远期热加载边界。

### 3.2 文件监听引擎

- fsnotify 递归 watch `~/.claude/projects/` 目录树，动态增删 watch。
- 每个 jsonl 文件维护 `{path → offset}` 内存态 + spool state 落盘持久化；启动时从当前末尾开始（不回溯历史日志），仅处理增量追加。
- 按 `\n` 切行解析，解析失败跳过并计数上报（不中断采集）。

### 3.3 断网缓存与重试

- 上行队列：内存 channel + 磁盘 spool（`~/.a3/spool/*.jsonl`，按批落盘）。
- 服务端不可达时全部入 spool；恢复后按序重放；指数退避（1s→60s 封顶）；服务端幂等保证重放无副作用。
- spool 容量上限（默认 512MB），满则丢最旧并记本地告警。

### 3.4 Hook 前置拦截（plugin-claude）

- 子命令：`a3-agent hook pretooluse`——stdin 读 ClaudeCode 原生 JSON（`{session_id, tool_name, tool_input}`）→ 本地规则判定：
  - 命中 `action=block` 规则 → stderr 输出中文拦截原因，exit code 2（ClaudeCode 原生协议阻断该工具调用，毫秒级）。
  - 未命中 → exit 0 放行；命中 `action=alert` 时异步生成 risk 事件走 file_log 同路上报。
- 安装：`a3-agent install-hook` 备份 `~/.claude/settings.json` 后合并写入 PreToolUse 配置（matcher 通配所有工具，command 指向本二进制绝对路径）；`a3-agent uninstall-hook` 还原。

### 3.5 预置规则集（plugin-claude/rules.go，代码内置）

| 类别 | Rule ID 示例 | 动作 |
|---|---|---|
| DLP | `dlp.aws_access_key`(AKIA…)、`dlp.private_key_block`、`dlp.generic_api_key`、`dlp.db_conn_string`、`dlp.jwt` | block/high |
| 高危命令 | `cmd.rm_rf_root`、`cmd.git_force_push`、`cmd.remote_script_exec`(curl\|sh)、`cmd.chmod_777`、`cmd.disk_wipe`(mkfs/dd) | block/high |
| 敏感文件 | `file.ssh_private_read`(~/.ssh/*)、`file.env_access`(.env)、`file.pem_read` | alert→block 可配/high |
| Git 高危 | `git.history_rewrite`(filter-branch/reset --hard) | alert/medium |

规则结构：ID、名称、类型（dlp/cmd/file/git）、匹配器（正则/路径模式）、severity、action、enabled。同一套结构入库 `rules` 表供服务端复用。

## 4. 服务端

### 4.1 鉴权

- **设备侧**：`POST /api/v1/devices/register`（携带机器指纹 hostname+mac hash）。单机模式默认开放自动注册并返回 token；分布式部署设 `A3_ALLOW_AUTO_REGISTER=false` 后改由控制台预生成 Token 手工下发。Token 仅明文返回一次，库存 SHA-256 哈希。
- **控制台**：环境变量种子管理员（`A3_ADMIN_USER/A3_ADMIN_PASSWORD`，首次启动创建），登录签发 JWT（HS256，8h）。

### 4.2 API 一览（/api/v1）

| 方法路径 | 用途 |
|---|---|
| POST /devices/register | 设备注册（可关） |
| POST /events/batch | 事件批量上报（设备 Token） |
| GET  /devices | 设备列表（在线状态=最后心跳 5min 内） |
| POST /auth/login、GET /auth/me | 控制台登录 |
| GET  /sessions | 会话检索（keyword/device_id/risk/时间范围/分页） |
| GET  /sessions/{id}/events | 回放事件流（时序全量） |
| GET  /sessions/{id}/export | 会话 JSONL 导出下载 |
| GET  /alerts、PATCH /alerts/{id} | 告警列表 / 确认处理 |
| GET  /alerts/export | 告警 CSV 导出 |
| GET  /rules、PATCH /rules/{id} | 规则查看/启停（一期仅启停，不做可视化编辑） |
| GET  /stats/overview | 首页概览数字 |

### 4.3 数据流

ingest（鉴权→校验→幂等落库）→ 异步规则引擎二次检测（对 tool_call/tool_result 内容跑启用规则，补打 RiskTag）→ 命中生成 alerts 记录 + 更新会话风险计数。会话组装：首见 session_id 建 sessions 行，事件到达滚动更新 title（取首条 user prompt 截断）/event_count/ended_at。

## 5. PostgreSQL 模型（migrations/0001_init.up.sql）

- `devices(id uuid pk, device_id text uniq, token_hash text uniq, hostname, os, arch, agent_version, status, first_seen_at, last_seen_at)`
- `sessions(id uuid pk, device_id text fk, agent_type, session_key text, title, started_at, ended_at, event_count int, risk_count int, uniq(device_id, session_key))`
- `events(event_id text pk, device_id text, session_key text, agent_type text, event_type text, role text, occurred_at timestamptz, payload jsonb, risk_tags jsonb, created_at)` + idx(session_key, occurred_at), idx(occurred_at)
- `alerts(id uuid pk, device_id, session_key, event_id, rule_id, rule_name, severity, action, snippet, summary, status open|acknowledged, created_at, acknowledged_at)` + idx(created_at), idx(status)
- `rules(id text pk, name, category, matcher jsonb, severity, action, enabled bool, builtin bool, created_at, updated_at)`

ClickHouse 预留：`store.EventStore` 接口 + `pgimpl`；后续 CH 实现仅需实现同接口接入配置开关。

## 6. Web 前端（Vue3 + Element Plus + Vite）

- 页面：登录页｜概览页（统计卡）｜会话列表（关键词/设备/风险过滤、分页）｜会话回放（左侧事件时间线，右侧渲染：user/assistant 对话气泡、工具调用折叠卡片显示 name+input JSON+output、风险红色 Tag 高亮）｜告警中心（列表+确认）｜设备管理（列表+在线状态）。
- 布局：Element Plus 经典后台框架（侧边菜单+顶栏），全中文文案。
- 导出按钮直连后端下载接口。

## 7. 部署

- `deploy/docker-compose.yml`（默认）：services = postgres + server(Gin，静态托管 web 构建产物) ；端口 8080 一站式；env 配置管理员种子、自动注册开。ClickHouse/MinIO 以注释块预留。
- 客户端：`make build-agent` 产出跨平台单二进制；单机模式默认连 `https://127.0.0.1:8080` 自动注册；分布式模式 `--server <url> --token <token>` 显式接入。
- 运行模式：前台常驻进程（一期），README 说明 launchd/systemd 开机自启配置示例；异常退出由进程管理器重启（符合"支持开机自启、异常自动重启"且不过度设计）。
