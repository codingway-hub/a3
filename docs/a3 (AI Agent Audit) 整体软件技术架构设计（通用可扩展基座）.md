# a3 \(AI Agent Audit\) 整体软件技术架构设计（通用可扩展基座）

## 1\. 设计目标

本文档定义**a3 开源项目全局通用技术架构**，为长期多 AI Agent 适配提供统一技术基座。

核心目标：**架构一次定型、永久复用；新增任意 AI Agent 无需修改核心基座**。

本文件为**全局宏观设计**，不包含任何版本、任何一期落地细节。

## 2\. 核心设计思想

采用 **基座与业务适配彻底解耦** 的插件化架构：

- **Core 基座**：永久稳定，负责采集调度、传输、存储、规则引擎、Web 服务、权限、告警。

- **Agent Plugin 插件层**：所有差异化逻辑（日志路径、字段解析、工具结构）全部下沉至插件。

任何新增 AI 工具（codex、trae、kilo、opencode 等）仅需开发对应插件，核心代码零改动。

## 3\. 全局分层架构（四层永久架构）

### 3\.1 终端采集层（插件化、可无限扩展）

终端采集器分为「通用 Core」和「Agent 插件」两部分。

**通用 Core 能力（全局统一）**

- 跨平台常驻后台能力（Linux / macOS / Windows）

- 文件事件监听引擎、进程检测引擎

- 本地断网缓存、加密队列、断点续传

- 插件热加载、插件状态自检、采集异常上报

- 本地策略拦截框架（通用拦截钩子、策略匹配、阻断执行器）

**插件层能力（差异化、可扩展）**

每个 AI Agent 对应一个独立插件，负责：

- 定义该 Agent 的日志路径、文件规则

- 解析私有日志格式、私有 tool 结构

- 将私有数据**标准化映射为 a3 统一事件结构**

- 适配该 Agent 的 Hook/回调机制

### 3\.2 统一传输层（全局通用）

与 Agent 类型完全无关，提供全站统一能力：

- HTTPS 加密上报

- 设备 Token 鉴权

- 事件去重、幂等处理

- 限流、批量上报、失败重试

### 3\.3 服务端基座层（永久不变）

服务端完全不感知具体 Agent 类型，只处理标准化事件。

包含核心模块：

- 事件接收与校验模块

- 会话组装引擎（通用，支持任意 Agent 会话回放）

- 通用风险规则引擎（DLP \+ 高危行为规则）

- 告警中心、事件标签体系

- RBAC 权限系统

- Web 审计控制台（通用列表、回放、检索、导出）

### 3\.4 统一存储层（全局结构固定）

存储结构**不区分 Agent 类型**，未来新增工具无需改表。

- **PostgreSQL**：设备、用户、会话元数据、告警、权限配置

- **ClickHouse**：全量不可篡改审计事件存储，用于合规检索、日志留存

- **对象存储（可选 MinIO）**：超大原始会话归档

## 4\. 全局核心规范（扩展基石）

### 4\.1 统一事件 Schema（最核心）

所有插件输出必须归一为 a3 标准事件结构，服务端只消费这一套结构。

包含：事件类型、会话ID、Agent类型、设备信息、用户Prompt、模型回复、工具调用参数、工具执行结果、风险标签、采集方式。

### 4\.2 通用规则引擎规范

规则与 Agent 解耦，一套规则适配所有工具：

- 通用 DLP 敏感信息规则

- 通用高危命令/文件操作规则

- 通用告警策略、拦截策略

### 4\.3 统一前端视图规范

会话列表、回放页、告警页、检索页**完全通用**，新增 Agent 无需开发新页面。

## 5\. 整体能力定位

a3 全局架构同时支持：

- **全量审计观测**：会话、对话、工具调用、执行结果全留存

- **主动安全防护**：终端本地策略拦截高危操作、阻断恶意行为

- **无限生态扩展**：插件化纳管所有未来 AI 编码 Agent

## 6\. 架构约束

- 所有 Agent 差异化逻辑禁止写入核心基座

- 所有新增工具必须通过插件方式接入

- 事件结构、存储模型、规则引擎长期兼容不破坏性变更

- 默认全私有化部署，数据不出内网
