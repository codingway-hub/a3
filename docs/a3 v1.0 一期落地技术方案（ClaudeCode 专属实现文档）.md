# a3 v1\.0 一期落地技术方案（ClaudeCode 专属实现文档）

## 一、文档说明与版本定位

本文档为 a3 项目 v1\.0 一期落地技术细则，基于《a3 整体软件技术架构设计（通用可扩展基座）》顶层架构规范落地，是插件化可扩展架构的首个验证版本。

本期基于开源 MVP 最小可用原则，确立两项核心建设目标，聚焦落地、适度留白，兼顾版本快速上线与长期架构扩展性：

1\. **基座架构完全对齐，实现最小可用骨架**：严格遵循顶层分层、插件化、标准化 Schema 设计，仅落地一期业务必需的基座能力，完整预留扩展接口，保持架构简洁轻量化。

2\. **全力聚焦 ClaudeCode 全场景适配**：本期唯一业务落地对象为 ClaudeCode CLI，所有差异化采集、解析、风控、拦截能力完整落地，保证版本可用、功能闭环。

本期核心原则：**架构不打折、能力不冗余、落地不堆砌**，既保障后续无限扩展兼容，又保证一期版本轻量化、可快速上线、无无效开发。

本期唯一适配对象：ClaudeCode CLI

## 二、V1\.0 建设范围与取舍设计

### 2\.1 本期核心建设内容（In Scope）

以「最小可扩展基座 \+ 完整ClaudeCode业务能力」为核心，实现可上线闭环版本：

- **最小通用基座骨架落地**：完成顶层架构分层落地、标准化事件Schema、插件挂载接口、基础传输鉴权、核心存储模型、基础Web审计骨架，保障架构合规、后续可扩展。

- **ClaudeCode 全量专属适配**：开发独立 claude 插件，实现日志监听、数据标准化解析、工具行为识别、会话拼装，完整适配ClaudeCode原生能力。

- **安全闭环能力落地**：实现终端本地DLP敏感检测、高危操作识别、前置进程拦截，解决ClaudeCode使用过程中的核心安全风险。

- **基础合规能力落地**：实现会话全量留存、风险告警、会话回放、审计日志导出，满足中小团队基础合规需求。

### 2\.2 本期明确舍弃的冗余能力（优化取舍）

为遵循轻量化落地、最小可用开发原则，顶层架构中部分远期通用能力，本期**只预留接口、不做完整实现**，统一延后至后续版本迭代：

- 不实现插件热加载、精细化终端自检、高级断网缓存策略等远期基座能力（仅预留插件挂载标准接口）。

- 不实现全量通用规则引擎后台配置、可视化策略编辑能力（本期代码预置Claude专属规则即可）。

- 不实现复杂RBAC权限、终端批量运维、高级告警聚合能力（保留基础权限、基础告警）。

- 不拓展网络网关、流量劫持、第三方SIEM对接、网页端AI管控等超出一期边界的能力。

- 不适配任何非ClaudeCode的AI Agent工具，专注单一场景打磨体验。

终端严格遵循「Core通用骨架 \+ 插件差异化实现」分层，Core只做基础支撑，所有业务能力由Claude插件落地，完全解耦，无基座硬编码适配。

基于轻量化落地原则，本期仅落地ClaudeCode适配场景必需的核心能力，严格对齐顶层架构规范，保证架构标准统一、功能简洁够用：

所有一期差异化、业务化能力全部收敛于独立 **plugin\-claude** 插件，是本期开发核心重心，完整实现ClaudeCode场景全能力适配：

- **数据标准化映射**：深度解析ClaudeCode私有JSONL对话、工具调用、执行结果结构，100%映射为顶层架构定义的a3标准事件Schema，保障服务端无需适配差异化数据。

- **前置Hook拦截适配**：对接ClaudeCode原生preToolUse钩子，在工具执行前完成风险检测，实现bash命令、文件读写、Git高危操作的毫秒级本地阻断，弥补日志后置审计的短板。

### 3\.3 终端整体运行流程

终端Core提供基础运行、传输、缓存、调度骨架，Claude插件承载场景化采集、解析、风控、拦截能力。双路采集联动生效：文件日志保障全量审计可追溯，Hook前置拦截保障风险可阻断，在轻量化架构的前提下，实现「观测\+防护」闭环能力。

## 五、存储层 V1\.0 实现（轻量化可落地）

本期采用「基础必选\+高级可选」的轻量化存储落地策略，在满足一期业务需求的同时，兼容远期完整分层存储架构，有效降低部署门槛：

- **PostgreSQL（必选）**：承载全部元数据、会话信息、设备用户、告警记录、基础配置，满足一期全部业务需求。

- **ClickHouse（可选）**：一期默认不强制部署，仅预留接入适配层；如需大规模合规审计、海量日志留存，可后续无缝开启，无需改业务代码。

- **MinIO（可选）**：针对超大原始会话日志归档，作为高阶能力可选部署，个人/小团队可直接省略。

方案优势：一期轻量化可用、低部署成本，可无缝迭代升级为完整分层存储架构，兼顾落地实用性与长期扩展性。

## 六、V1\.0 技术栈与部署

### 6\.1 技术栈

沿用顶层架构标准技术栈，保证架构统一性，无自定义非标组件：

- 终端采集器：Go（跨平台单二进制、轻量高性能、适配插件化架构）

- 服务端：Go \+ Gin（高并发、适配日志上报场景）

- 前端：Vue3 \+ Element Plus（轻量化企业审计后台）

- 存储：PostgreSQL 为主，ClickHouse/MinIO 为可选拓展

### 6\.2 部署方式（服务端 / 客户端 分离部署）

a3 v1\.0 架构原生支持服务端、客户端解耦分离部署，为兼顾**开源用户易用性**与**架构长期规范性**，本期提供两种部署模式：默认主推轻量化单机一体化部署，同时预留进阶分布式分离部署能力，适配个人单机使用、团队多终端接入两类场景，严格匹配一期最小可用架构定位。

#### 6\.2\.1 部署模式一：单机一体化部署（v1\.0 默认主推）

适配绝大多数个人开发者、单机开发场景，服务端与客户端均部署在同一本地设备，极简部署、零复杂配置，完全契合MVP轻量化设计理念。

- 部署形态：Docker Compose 一键部署服务端，本地直接运行客户端二进制文件

- 运行特点：本地闭环运行，无需公网地址、无需跨网络配置

- 接入逻辑：本地客户端默认绑定本机服务端，自动完成Token初始化鉴权，无需手动配置

- 组件配置：默认启用Web前端、核心服务、PostgreSQL基础存储，默认关闭ClickHouse、MinIO高阶组件

- 适用场景：个人日常ClaudeCode开发审计、单机风险防护、本地合规留存

#### 6\.2\.2 部署模式二：分布式分离部署（v1\.0 进阶可选）

适配小型团队多终端统一管控场景，服务端独立部署在内网服务器，各开发者终端独立部署客户端，实现多设备统一纳管、统一审计、统一风险策略。本期仅支持单服务端节点部署，不支持集群扩容，规避超出一期轻量化架构的过度设计。

- 部署形态：服务端内网服务器容器化部署，各终端独立部署客户端二进制

- 网络要求：所有客户端与服务端内网互通，全程HTTPS加密传输

- 设备鉴权：服务端生成唯一设备Access Token，客户端配置Token完成绑定接入，杜绝非法终端接入

- 组件配置：可按需开启ClickHouse海量日志存储、MinIO会话归档能力

- 适用场景：小团队多终端ClaudeCode行为统一审计、批量风险管控、团队合规落地

服务端基于容器化方案实现标准化部署，统一承载数据存储、规则计算、审计管理、Web控制台能力，无本地环境依赖，部署稳定、运维简单。

- 部署载体：Docker Compose 容器化一键部署

- 运行环境：内网私有化部署，全量数据不出内网环境

- 基础组件：Web前端、Gin后端服务、PostgreSQL核心存储（默认必装）

- 扩展组件：ClickHouse、MinIO（按需手动开启，非强制依赖）

- 核心能力：统一接收终端上报事件、风险规则校验、会话数据持久化、审计回放、风险告警、终端权限管控

#### 6\.2\.3 客户端部署规范

客户端为 **Go 编译单二进制文件**，跨平台无依赖，无需 Docker，直接终端后台常驻运行，对开发者完全无侵入。

客户端采用轻量级单二进制部署方案，跨平台无依赖、无侵入安装，仅负责本地采集、风险拦截、数据标准化上报，全程静默运行，不干扰开发者正常工作流。
